# 管理后台
入口：http://localhost:3100/admin 。独立登录页：/admin/login。
管理员使用独立用户名与密码登录接口 `/api/admin/login`，要求 User.role=ADMIN 且 ACTIVE。管理员不能从用户邮箱登录入口登录。公开注册不接受权限字段；管理员由命令行建立，第二个参数为唯一用户名（3至32位英文字母、数字、下划线或连字符，不区分大小写）：
```bash
node --env-file=.env --import tsx scripts/admin.ts admin@example.com admin
```
已有账户保留密码；新账户生成随机初始密码，打印一次用于交付，不写入代码或配置文件。

## 已实现功能
- 概览：实际累计用户、24 小时聊天活跃用户、公开角色、待审核数、成功对话、7 日趋势、真实/模拟充值分开统计、待办与近期操作。
- 用户管理：搜索、状态筛选、游标分页、正常/冻结切换、冻结撤销全部登录会话。禁止通过网页冻结管理员。
- 钱包：带原因的增减调整，同事务写余额/流水/审计；请求 UUID 幂等并用事务锁防重复提交；余额不能为负。
- 角色：新增官方角色、编辑已提交资料、单价设置、审核通过/驳回、下架/重新审核。用户私密草稿不可见，用户从“我的角色”主动申请公开。
- 订单：查看、筛选、分页；Stripe 待支付订单主动核验，只有服务端匹配支付平台的订单/币种/金额/支付状态才入账；无手工虚构到账操作。
- 流水与操作日志：搜索、分页和当前页 CSV 导出；文本转义防止表格公式注入。
- 异常请求：对超过五分钟的 PENDING 聊天执行幂等退款对账。
- 系统状态：数据库/Redis 探测、模型及支付是否配置、实际套餐；不暴露秘钥，生产配置仍由部署环境管理。

## 验证
npm run typecheck
npm run build
node --env-file=.env --import tsx --test tests/admin-integration.ts
浏览器实测管理员登录、筛选、编辑对话框、余额调整与桌面/手机布局。

## 边界
后台未包含支付退款/争议处理、精细化多级 RBAC、后台配置秘钥、统计数仓、批量群发或私密聊天全文查看。角色审核为人工操作，真实内容审核仍依赖已配置的模型与运营流程。分页每页20条。时间显示使用 Asia/Shanghai。
