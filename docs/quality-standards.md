# 06 · 质量门禁与验证标准

## 功能门禁
注册/登录/退出；私密角色授权；卡片搜索与筛选；创建后可聊天；刷新恢复记录；余额不足拒绝；上游失败退款；重复请求重放；支付重复回调只入账一次。每条必须有自动化或可复查人工证据。
## 金融与安全门禁
- 钱包与流水和差异为零；至少 100 并发同订单回调及同请求退款测试，故障注入后无重复到账。
- 接口拒绝未登录、跨用户访问、跨 Origin 写入、伪造金额、伪造签名、重复 UUID 改内容及超长请求。
- bcrypt、HttpOnly cookie、会话撤销和角色 prompt 不下发；生产 HTTPS；密钥从 Secret 注入。
- 注册需要邮件验证和防滥用策略上线后才能对公众无限开放；现有账户/全局限流并不足以阻止分布式刷赠币。
- 内容安全必须真实模型联调、攻击样例评测和举报处置；审核模型本身不是绝对安全保证。
- npm audit 高危/严重为 0；类型检查、生产构建、数据库迁移、单元与集成测试全部通过。
## 性能标准（验收目标，不是当前测量结果）
在约定云环境和固定数据集上测量：角色列表 500 RPS 持续 15 分钟，P95 <300ms、P99 <800ms、错误率 <1%；认证 P95 <1s；峰值收费生成 232 RPS 持续 30 分钟，再 464 RPS 验证余量。
真实模型完整审核回复 P95 <15s、成功率 ≥99%；由于输出审核缓冲，本版不承诺用户首字 <2s。不同角色/长上下文单独分桶统计。
使用负载发生器与应用分机部署，避免本机 CPU 争抢。每虚拟用户独立预充值账户；单账户压测会触发预期限流，不能冒充平台容量瓶颈。
scripts/load-test.js 为目录负载；scripts/load-chat.js 是 100 VU 聊天起点，真实 232/464 RPS 验收需调整 arrival-rate、账户量及账户频率，确保足够模型配额。真实模型压测会产生账单，需预算后运行。
## 浏览器与可访问性
桌面 1440×1000、手机 390×844 及 320px 最小宽度无横向溢出、遮挡或不可点击控件；全部图片加载成功；键盘焦点可见、表单标签正确、错误可读、IME Enter 不误发送。登录、充值、私密角色创建及发送必须实际点击，不仅检查路由 200。
## 模型质量
200 条固定评测集；角色一致性/任务完成平均 ≥4/5；严重安全失败 0；对高风险领域不冒充专业人士。记录模型 ID、设定版本、输入摘要、评分、成本和延迟。模型切换需要重跑。
## 恢复与发布
通过数据库 PITR 恢复、Redis 中断、模型超时、支付重放、生成中 Pod 终止演练。目标 RPO ≤5 分钟、RTO ≤30 分钟。未通过的门禁不得用“预计支持”替代实测。
## 测试入口
```bash
npm test
npm run test:integration
npm run typecheck
npm run build
npm audit --audit-level=high
docker compose config --quiet
k6 run scripts/load-test.js
```
集成测试需要 demo 模式服务与数据库/Redis，创建独立 qa 邮箱；测试数据保留用于复查，不对生产执行。
